# CAELUS (Electron UI)

Claude Code CLI를 두뇌로 쓰는 CAELUS의 프론트엔드. UI는 입력을 받아 CLI에
전달하고 응답을 렌더링만 하며, 실제 처리(코드 실행/파일 조작 등)는 전부
Claude Code CLI가 담당한다.

## 구조

```
src/
├── main/
│   ├── main.js             BrowserWindow 생성, 단일 인스턴스 락, IPC 핸들러 전체
│   ├── claudeBridge.js      Claude Code CLI child_process 래퍼 (--print 모드, 세션 연속성/취소/cwd 지원)
│   ├── store.js             작업 기록(SESSION/TASK/LOG) + 프로젝트별 활성 대화 스레드 JSON 저장소 (원자적 쓰기)
│   ├── credentialsGuard.js  CLI 로그인 토큰 백업/자동 복구
│   └── preload.js           contextBridge로 렌더러에 안전하게 API 노출
└── renderer/
    ├── index.html        사이드바 + 원형 상태 인디케이터 + 대화창 + 입력바 + 각종 컨트롤
    ├── styles.css         JARVIS 스타일 네온 팔레트/글로우 이펙트 + 라이트 테마
    └── renderer.js        상태 전이, 대화 렌더링, IPC 호출, UI 상호작용 전체
```

## 최초 1회 설정 (인터넷 필요)

```
cd electron-app
npm install
```

USB 내부에 `node_modules`가 생성된다. 이후에는 오프라인 환경(다른 PC)에서도
`start.bat`이 그대로 `node_modules\.bin\electron.cmd`를 실행한다.

## 개발 중 직접 실행

```
npm start
```

## Claude Code CLI 연동 방식

- `claudeBridge.js`가 `claude --print`를 `child_process.spawn`으로 호출한다.
  사용자 프롬프트는 명령줄 인자가 아니라 **stdin으로 전달**한다 — Windows에서
  이 프로세스는 shell:true로 cmd.exe를 거쳐 실행되는데, 사용자가 입력한
  문장에 괄호/`&`/`%`/`^` 같은 cmd.exe 특수문자가 섞이면 명령줄 자체가 깨져서
  프롬프트가 잘리거나 다른 인자와 뒤섞이는 문제가 실사용 중 확인됐다. stdin은
  셸 파싱을 거치지 않으므로 사용자가 뭘 입력하든 안전하다.
- CLI 실행 파일 경로는 기본적으로 PATH의 `claude`를 사용하며,
  `CAELUS_CLAUDE_CMD` 환경변수로 재정의할 수 있다.
- **대화 연속성**: 프로젝트마다 `store.js`의 `activeThreads` 맵에 지금
  이어지고 있는 Claude 대화 스레드(uuid)를 기억해둔다. 그 프로젝트로 다시
  메시지를 보내면 `main.js`가 그 uuid를 `claudeBridge.js`에 넘기고,
  `claudeBridge.js`는 `--resume <uuid>`로 CLI를 호출해 실제로 이전 대화를
  기억한 채 이어간다(활성 스레드가 없으면 새 uuid로 `--session-id`를 써서
  새로 시작). `--resume`이 실패하면(예: 어떤 이유로 그 스레드를 CLI가 못
  찾음) `isResumeFailure()` 휴리스틱으로 감지해 새 스레드로 한 번 폴백
  재시도한다.

  > ✅ **실기기 확인됨(성공 케이스)**: `claude --print --session-id <uuid>
  > "이름은 철수야"` 후 `claude --print --resume <uuid> "이름이 뭐였지?"`를
  > 실기기에서 직접 실행해 "철수"라고 정확히 기억하는 것을 확인했다 —
  > `--session-id`/`--resume` 조합 자체는 실제로 동작한다.
  >
  > ⚠️ **실기기 미검증(실패 케이스)**: 반대로 **잘못된**(존재하지 않는)
  > `--resume` 값이 실제로 종료코드 nonzero + stderr로 실패하는지, 아니면
  > 조용히 "그런 세션 없음" 내용을 종료코드 0의 정상 응답으로 뱉는지는
  > 아직 확인 안 됐다. 후자라면 `isResumeFailure()`의 폴백 재시도가
  > 트리거되지 않는다 — `claude --print --resume
  > 00000000-0000-0000-0000-000000000000`로 확인 필요.

  > 🐛 **발견 후 수정됨(경쟁 상태)**: 메시지 전송 중(`isBusy`)에 사이드바의
  > 스레드 삭제/프로젝트 이름변경·삭제 버튼을 누르면, 그 요청이 끝나면서
  > `store.setActiveThread`가 activeThreads를 무조건 다시 덮어써서 방금
  > 지운/바꾼 포인터가 되살아나는 문제가 있었다(`clearAll()`이
  > activeThreads를 안 지우던 버그와 같은 계열, 다른 경로로 재발). 세
  > 버튼 핸들러에 `if (isBusy) return;` 가드를 추가해 막았다 — jsdom
  > 테스트로 수정 전엔 재현되고 수정 후엔 안 됨을 확인했다.
- `start.bat`이 `PATH`에 portable `node`/`git`을 추가하고 `CAELUS_HOME`
  환경변수를 `claude-home`으로 설정해둔 상태에서 이 앱이 실행된다.
  `claudeBridge.js`는 CLI를 spawn할 때 **그 자식 프로세스에만**
  `HOME`/`USERPROFILE`을 `CAELUS_HOME`으로 덮어써서, CLI의 인증/세션
  저장 위치를 USB로 고정한다.
  - **주의**: Electron 프로세스 자체의 `HOME`/`USERPROFILE`은 절대 건드리지
    않는다. 예전에는 `start.bat`이 세션 전체의 `HOME`/`USERPROFILE`을
    재설정했는데, 그러면 Electron 내부 Chromium이 프로필 경로 계산 중
    조용히 비정상 종료(창이 아예 안 뜸)하는 문제가 실사용 테스트에서
    확인됐다. `store.js`도 같은 이유로 `CAELUS_HOME`을 최우선으로 읽는다.

## 대화 / 코딩 모드

Claude Code CLI의 기본 시스템 프롬프트는 "파일을 함부로 안 건드리는 신중한
코딩 에이전트"로 튜닝돼 있어서, `--print` 모드로 일반 잡담이나 산수 질문을
던져도 "무엇을 하시려는 건가요?" 하고 자꾸 되묻는 경향이 있다(실사용 중
확인됨). 명령 입력바 위 토글로 두 모드를 전환할 수 있다.

- **대화**(기본값) — `claudeBridge.js`가 `--append-system-prompt`로 "일반
  채팅처럼 자연스럽게 답하라"는 지시를 얹어서 호출한다.
- **코딩** — 아무것도 얹지 않고 CLI 기본 동작(신중한 에이전트) 그대로
  호출한다. `projects\` 안의 실제 코드 작업을 시킬 때는 이 신중함이
  필요하므로 이쪽을 쓴다.

선택한 모드는 `localStorage`에 기억되고(브라우저별 편의 저장, 작업 기록
자체에는 영향 없음), 각 작업의 모드는 사이드바 기록에도 표시된다.

## USB 안전성 (예고 없이 뽑히는 것에 대한 대비)

USB는 언제든 예고 없이 뽑힐 수 있는 매체라는 전제로 아래 세 가지를 넣어뒀다.
자세한 배경은 `README.md`의 "알려진 제약" 참고.

1. **작업 기록 손상 방지** — `store.js`가 파일을 직접 덮어쓰지 않고 임시
   파일 + rename으로 원자적으로 쓴다. 혹시 손상된 파일을 만나도 조용히
   버리지 않고 `.corrupted-<timestamp>.bak`으로 백업한다.
2. **로그인 세션 손상 대비** — `credentialsGuard.js`가 매 실행마다 CLI의
   로그인 토큰이 정상이면 백업하고, 손상돼 있으면 백업에서 자동 복구한다.
3. **중복 실행 방지** — `main.js`가 `app.requestSingleInstanceLock()`으로
   같은 PC에서 CAELUS가 두 번 뜨는 것을 막는다(자동실행 트리거가 걸린
   PC에서, 죽지 않은 이전 창이 있는데 USB가 재삽입되는 경우 대비). 이
   락은 USB가 아니라 그 PC의 실제 Windows 프로필에 저장되므로, 여러
   PC에서 각자 CAELUS를 쓰는 정상적인 사용에는 영향을 주지 않는다.

앱이 완전히 로딩되기 전(Electron이 자신의 JS 파일을 USB에서 읽는 도중)에
USB가 뽑히는 경우는 그 시점에 아직 JS 코드가 안 떠 있어 앱 내부에서 막을
수 없다 — `start.bat`이 비정상 종료를 감지해 한 번 자동 재시도하고, 그래도
실패하면 안내 메시지를 띄우는 것으로 대응한다.

## 그 외 기능들

- **사이드바 = 프로젝트/스레드 트리** — Claude 앱처럼 사이드바가 "프로젝트"
  섹션(프로젝트별로 접고 펼 수 있는 그룹, 그룹 헤더 클릭은 펼치기/접기만
  하고 활성 프로젝트는 안 바꾼다)과 고정된 "기타 대화"(`general`) 섹션으로
  나뉜다. 각 그룹 안 항목은 task 하나가 아니라 **스레드(대화) 하나**를
  대표하며, 클릭하면 그 스레드에 오간 모든 턴을 시간순으로 대화창에 전부
  띄운다(`viewThread`). 검색창을 쓰면 그룹 구분 없이 전체에서 평평하게
  찾아준다(각 항목에 프로젝트 이름 태그 표시).
- **이어서 대화하기** — 지금 활성 스레드가 아닌 과거 스레드를 보고 있으면
  대화창 위에 "이어서 대화하기" 배너가 뜬다. 누르면 그 스레드를 다시 그
  프로젝트의 활성 스레드로 지정해서 진짜로 이어갈 수 있다.
- **새 대화 시작** — 상태 표시줄(또는 그룹 헤더의 `+` 아이콘)의 "새 대화
  시작"을 누르면 그 프로젝트의 활성 스레드 포인터만 지운다(과거 기록은
  안 지워짐) — 다음 메시지부터는 완전히 새 대화로 시작한다.
- **대화가 길어지면 안내** — 실제 토큰 수를 로컬에서 잴 방법이 없어서, 한
  스레드의 턴 수가 15턴을 넘으면 상태 표시줄 아래 "새로 시작하면 더 빠르고
  정확할 수 있어요" 안내를 보여준다(대략적인 휴리스틱).
- **제목 수동 수정 / 프로젝트 이름변경·삭제** — 사이드바 항목의 연필
  아이콘으로 대화 제목을, 그룹 헤더의 연필/휴지통 아이콘으로 프로젝트
  이름을 바꾸거나 프로젝트 폴더 자체를 삭제할 수 있다. **삭제는 실제
  파일시스템 삭제**(그 폴더 안 실제 작업 파일까지 영구 삭제)라 확인 문구를
  거친다 — 지금까지 나눈 대화 기록 자체는 지우지 않고 "기타 대화" 그룹으로
  자동 재배치된다(고아 데이터 방지). `general` 폴더는 이름변경/삭제 버튼이
  아예 없다(예약된 폴더).
- **검색 / 개별·전체 삭제** — 검색창으로 제목 필터링, 스레드별 삭제(그
  스레드의 모든 턴을 함께 지움), 전체 삭제(설정 패널의 휴지통 아이콘)를
  지원한다.
- **실시간 스트리밍 표시** — CLI가 stdout으로 내보내는 대로 응답 말풍선이
  바로바로 채워진다.
- **요청 취소** — 응답 대기 중 "취소" 버튼으로 그 자식 프로세스를 강제
  종료할 수 있다.
- **코드 블록 렌더링** — 응답에 포함된 ` ```코드``` ` 펜스와 인라인 `` `코드` ``
  를 가볍게 렌더링한다(외부 마크다운 라이브러리 없이 직접 구현 — USB에
  의존성을 더 안 늘리기 위함).
- **응답 복사** — 말풍선에 마우스를 올리면 복사 버튼이 뜬다.
- **대화 내보내기** — 지금 화면에 보이는 대화를 마크다운 파일로 저장한다.
- **작업 폴더(프로젝트) 전환** — 사이드바 트리에서 프로젝트 그룹을 고르면
  (더 정확히는 그 그룹의 `+`/이어서 대화하기로 활성화하면) CLI가 그 폴더를
  작업 디렉터리로 삼아 실행된다. `general`("일반 (자동 정리함)")은 항상
  "기타 대화" 섹션에 고정돼 있고, 프로젝트를 따로 안 고르고 하는 일반
  대화/작업이 자동으로 여기 모인다 — `projects\` 루트 자체를 작업
  디렉터리로 쓰지는 않는다(그러면 프로젝트로 안 묶인 파일들이 루트에 바로
  쌓여 지저분해진다). 예전에는 이 cwd를 아예 명시적으로 안 넘겨서 Electron
  프로세스 자신의 cwd(`electron-app` 폴더)를 그대로 썼던 게 실제로는
  버그였다.
- **새 프로젝트 폴더 만들기** — "프로젝트" 섹션 라벨 옆 `+` 버튼을 누르면
  그 자리에 이름 입력창이 뜬다(Enter로 생성, Esc로 취소). 처음엔
  `window.prompt()`로
  만들었는데, **Electron이 `window.prompt()`를 지원하지 않아**(호출해도
  다이얼로그가 안 뜨고 조용히 무시됨) 버튼이 아예 반응 없는 것처럼 보이는
  문제가 실사용 중 확인됐다 — 화면에 직접 입력창을 넣는 방식으로 바꿔
  해결했다. `window.alert()`/`window.confirm()`은 Electron이 네이티브
  다이얼로그로 지원하므로 삭제 확인 등에는 계속 그대로 쓴다.
- **자주 쓰는 명령(프리셋)** — 명령 입력바 위 버튼을 누르면 입력창에
  채워진다(바로 전송하지 않음 — 보내기 전에 확인/수정할 수 있게).
- **사용량 링크** — 사이드바의 "Claude 사용량 보기" 버튼을 누르면
  `claude.ai/settings/usage`가 브라우저로 열린다. 처음엔 이 USB의 로컬
  작업 기록만으로 사용량 %를 추정해서 보여주려 했으나, 세션(5시간)/주간
  한도 %는 Claude 계정(구독 플랜) 자체의 정보라 CLI(`claude --help`에
  관련 명령 없음 확인)나 이 코드로는 조회할 공식적인 방법이 없다 — 그래서
  흉내내는 대신 실제 페이지로 바로 연결하는 방식으로 바꿨다.
- **자체 업데이트 확인** — "업데이트 확인" 버튼이 `git fetch` 후 origin과
  비교해 새 커밋이 있는지 알려준다. **자동으로 pull하지는 않는다** — 실행
  중인 작업에 영향을 주거나 검증 안 된 코드가 조용히 들어오는 걸 막기 위해,
  발견만 하고 실제 반영은 사용자가 직접 `git pull` 하도록 남겨둔다.
- **다크 / 라이트 테마** — 톱니바퀴(설정) 패널 안에서 전환, `localStorage`에
  기억됨.
- **알림음** — 응답 완료/오류 시 Web Audio API로 합성한 짧은 비프음(외부
  오디오 파일 없이 코드로 생성 — 자산 관리 부담 없음).

## 비주얼 리뉴얼 (프로토타입 티 벗기기)

기능이 늘면서 사이드바가 버튼 여러 개로 복잡해지길래, 시각적 완성도와
함께 다시 정리했다.

- **설정 패널** — 테마/사용량 링크/업데이트 확인/전체 삭제처럼 자주 안 쓰는
  것들은 톱니바퀴 아이콘 뒤 드롭다운 패널로 몰아넣었다. 사이드바 본체에는
  검색창 + 작업 기록 목록만 남는다.
- **빈 상태 안내** — 대화창이 비어 있을 때, 기록이 하나도 없을 때 각각
  안내 문구를 보여준다(예전엔 그냥 빈 화면).
- **HUD 느낌 강화** — 원형 인디케이터 바깥에 천천히 도는 점선 궤도, 무대
  네 모서리에 브래킷 장식을 넣어 JARVIS 느낌을 더했다. 상태별 색상(청록/
  황색/초록/빨강)은 궤도에도 그대로 반영된다.
- **커스텀 스크롤바, 통일된 간격/모서리 반경 스케일, 브랜드/상태 텍스트에
  모노스페이스 폰트** 등 자잘하지만 "만들다 만 것" 같은 인상을 주던
  디테일들을 정리했다.
- 새 폰트나 아이콘 파일을 CDN에서 받아오지 않는다 — 전부 시스템 폰트/CSS로
  구현해서 오프라인에서도 그대로 보인다(이 프로젝트의 "USB 안에서 최대한
  자급자족" 원칙 유지).

## 두 번째 비주얼 리뉴얼 (글로우 절제)

위 리뉴얼 이후에도 "여전히 프로토타입 같다"는 피드백을 받고 다시 파봤더니,
원인은 새로운 요소 부족이 아니라 **글로우가 기본 상호작용 신호로 남용된
것**이었다(아이콘 버튼/카드/뱃지/전송 버튼 등 거의 모든 곳이 hover 시
빛나서 정작 강조가 필요한 곳이 안 두드러짐). 사용자가 올려준 JARVIS UI
레퍼런스 영상(YouTube Shorts, "Making the UI for Jarvis")과 Claude.ai/
ChatGPT/오픈소스 채팅 UI(Open WebUI 등) 리서치가 같은 결론을 가리켰다 —
"컨셉은 유지하되 절제해서 마감".

- **동심원 JARVIS 링** — 기존 단일 링 안에 얇은 화이트 링을 하나 더
  넣어 레퍼런스처럼 레이어감을 줬다(`.ring-inner`).
- **점 패턴 배경** — 단색 배경 대신 은은한 점(별자리) 패턴 + 깊은
  그라디언트를 겹쳤다.
- **글로우는 링과 활성 강조 한 곳에만** — 아이콘 버튼/카드/프리셋/모드
  토글/입력창 등에서 hover 시 나던 box-shadow 글로우를 다 빼고 테두리/
  배경색 변화로 바꿨다. 유일하게 새로 추가한 포인트는 입력창에 텍스트가
  있을 때 테두리가 골드(`--accent-gold`)로 바뀌는 것 하나뿐 — 레퍼런스의
  "ENTER PASSWORD" 네온 입력창에서 가져온 디테일.
- **말풍선 비대칭** — 사용자 메시지만 카드(테두리+배경)로 감싸고, AI
  응답은 배경 없는 순수 텍스트 블록으로 바꿨다(Claude.ai/ChatGPT 공통
  패턴). 컨테이너 유무 자체가 "누가 말했는지" 신호가 되므로, 기존에
  역할마다 다른 색으로 빛나던 작은 점 마커는 없앴다.
- **타이포그래피 정리** — 사이드바 라벨류(대문자+넓은 자간+모노스페이스)를
  일반 UI 텍스트로 되돌리고, 모노스페이스는 브랜드명/JARVIS 상태 텍스트/
  기록 메타데이터처럼 실제 "HUD 판독값" 성격의 텍스트에만 남겼다.
- **그림자 통일** — 버튼 하나하나의 그림자를 없애고, 실제로 화면 위에
  "떠 있는" 레이어(설정 패널)와 대화 카드 두 곳에만 공용 그림자 토큰을
  씀.
- **스크롤바** — 평소엔 안 보이다가 그 영역에 마우스가 있을 때만 나타남.

구조(사이드바 트리, 스레드 뷰 등)는 전혀 안 건드리고 스타일만 다시
입혔다 — 회귀 여부는 기존 jsdom 테스트(프로젝트 트리 렌더링, activeProject
전환, isBusy 경쟁 방지)를 새 마크업/CSS로 다시 돌려서 확인했다(전부 통과).

## 알려진 제약

- 음성 입력(STT)/출력(TTS)은 아직 구현되어 있지 않다. 로컬 Windows
  TTS(SAPI5)는 품질이 상당히 기계적이라, 붙이더라도 무료 대안(예:
  edge-tts) 또는 유료 API 품질 검증을 먼저 거칠 계획이다.
- 병렬로 여러 대화를 동시에 진행하는 기능(탭/멀티 세션)은 아직 없다 — 한
  번에 하나의 요청만 처리하며, 진행 중에는 입력창이 잠긴다.
- 실제 사용량 %는 CAELUS 안에서 직접 안 보여주고 `claude.ai/settings/usage`
  로 연결만 한다 (위 "사용량 링크" 참고).
- Claude Code CLI의 정확한 CLI 플래그(`--session-id`/`--resume`/
  `--append-system-prompt` 등)는 설치된 버전에 따라 달라질 수 있으므로,
  버전 업데이트 시 `claudeBridge.js`의 인자 구성을 다시 확인해야 한다.
- `--resume`이 실패했을 때의 실제 CLI 동작(종료코드/stderr로 실패하는지,
  조용히 새 응답을 뱉는지)이 실기기에서 아직 검증되지 않았다 — 위 "대화
  연속성" 항목의 ⚠️ 참고.
- 같은 스레드 안에서 대화/코딩 모드를 왔다갔다 전환하면 `--append-system-
  prompt`가 매 턴 있다 없다 하게 되는데, CLI가 이걸 자연스럽게 처리하는지
  실기기 검증이 더 필요하다(치명적이진 않을 것으로 예상).
- 자체 업데이트 확인은 `git\bin\git.exe`가 있어야 동작하고, 네트워크가
  막혀 있으면(사내 프록시 등) 조용히 "확인 실패"로 표시된다.
